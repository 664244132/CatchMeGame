# TypeScript Coding Guide

**ข้อกำหนดและแนวทางปฏิบัติที่ดีสำหรับการเขียน TypeScript** เพื่อรักษาคุณภาพและความปลอดภัยของโค้ด

---

### 1. Type Inference vs. Explicit Boundaries
แนะนำให้กำหนดประเภทข้อมูล (Type) อย่างชัดเจนบริเวณรอยต่อ (**Public Boundaries** เช่น Input/Output ของฟังก์ชัน และ API Contracts) แต่ปล่อยให้ตัวแปรภายในประเมินประเภทข้อมูลโดยอัตโนมัติ (**Type Inference**) เพื่อไม่ให้โค้ดรกรุงรัง

### 2. Narrowing `unknown`
ปฏิบัติต่อข้อมูลนำเข้าจากภายนอกหรือข้อมูลที่ไม่น่าเชื่อถือเป็น `unknown` เสมอ และบังคับให้ทำ **Runtime Validation** ก่อนปล่อยให้เข้าสู่ระบบ

### 3. Avoiding Unsafe Assertions
หลีกเลี่ยงการทำ Type Assertion (การใช้คำสั่ง `as`) เพื่อปิดปาก Compiler แต่ให้พิสูจน์โครงสร้างข้อมูลจริงที่รันไทม์ (**Runtime Proof**) แทน โดยเฉพาะจุดเชื่อมต่อกับ JSON หรือข้อมูลจากเน็ตเวิร์ก

### 4. Discriminated Unions
ออกแบบ Model สถานะที่เกี่ยวข้องกันด้วยคุณลักษณะแบ่งแยก (**Discriminant Property** เช่น `status`) เพื่อช่วยให้เรียกใช้งานได้ปลอดภัย และป้องกันไม่ให้เกิดสถานะที่เป็นไปไม่ได้ในโครงสร้างโปรแกรม (Invalid States)

### 5. Exhaustive Checks with `never`
ตรวจสอบความครอบคลุมของสถานะทั้งหมดในคำสั่งเงื่อนไขผ่าน Type `never` เพื่อให้ระบบแจ้งเตือนข้อผิดพลาดตั้งแต่ตอนคอมไพล์หากมีการเพิ่มสถานะใหม่ในอนาคต

### 6. Precise Function Types
กำหนดรูปแบบอาร์กิวเมนต์และค่าส่งคืนของฟังก์ชัน Callback อย่างเฉพาะเจาะจง หลีกเลี่ยงการใช้ชนิดข้อมูลกว้างๆ ที่ไม่ปลอดภัยอย่าง `Function`

### 7. Optional Properties vs. Nullable Values
แยกแยะระหว่างการไม่มีฟิลด์นั้นอยู่ (**Optional** `?` สำหรับกรณีที่อาจละเว้นได้) กับการจงใจกำหนดให้ฟิลด์นั้นว่างเปล่า (**Nullable** `null`) เพื่อไม่ให้ผู้ใช้งานสับสน

### 8. Generic Constraints
ใช้คำสั่ง `extends` เพื่อกำหนดข้อจำกัดให้กับ Generic เสมอ ช่วยรักษาความยืดหยุ่นของฟังก์ชันแต่ยังสามารถเข้าถึงคุณสมบัติที่จำเป็นภายในโค้ดได้อย่างปลอดภัย

### 9. Utility Types at API Boundaries
ใช้ Utility Types อย่าง `Pick`, `Omit`, `Partial`, หรือ `Readonly` เพื่อสร้างรูปแบบข้อมูลเฉพาะขอบเขต API (**Boundary-Specific Contracts**) โดยไม่เปิดเผยฟิลด์ภายในของระบบที่ไม่จำเป็นให้กับผู้เรียกใช้

### 10. Type-Only Imports and Module Boundaries
บังคับใช้ `import type` ทุกครั้งที่นำเข้าเฉพาะประเภทข้อมูล เพื่อลดขนาดพึ่งพาของโมดูลในระดับรันไทม์ (**Runtime Dependencies**) และทำให้โครงสร้างโมดูลเบาลง

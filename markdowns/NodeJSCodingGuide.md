# NodeJS Coding Guide

**ข้อกำหนดและแนวทางปฏิบัติในการเขียนโค้ด NodeJS**

1. **การแยกกระบวนการเริ่มต้นออกจากสถาปัตยกรรมแอปพลิเคชัน (Runtime Boundaries):**
   แยกการทำงานของสิทธิ์การเชื่อมต่อและการเปิดพอร์ต (listen) ออกจากโมดูลหลัก เพื่อให้แอปพลิเคชันสามารถนำไปทดสอบ (Unit Test) หรือนำไปใช้ซ้ำในกระบวนการอื่นได้ง่ายโดยไม่มีผลกระทบแอบแฝง

2. **การทำงานกับไฟล์แบบไม่บล็อกโปรเซส (Async Filesystem):**
   หลีกเลี่ยงการใช้ฟังก์ชันระบบไฟล์ประเภทประสานเวลา (Synchronous I/O) ภายใน Request Path เพื่อป้องกันไม่ให้เกิดอาการหน่วงเมื่อระบบรองรับจำนวนผู้ใช้งานจำนวนมากพร้อมกัน

3. **ขอบเขตการดักจับข้อผิดพลาด (Async Failure Boundaries):**
   ดักจับและจัดการ Rejected Promises ที่ฝั่ง HTTP Boundary เสมอ เพื่อทำหน้าที่บันทึกประวัติข้อผิดพลาดและส่ง Response กลับไปให้ผู้ใช้งานได้อย่างถูกต้องโดยไม่ทิ้งปัญหาให้ค้างไว้

4. **การจัดการตัวแปรสภาพแวดล้อมอย่างมีระบบ (Environment Variables & Config):**
   รวบรวม ตรวจสอบประเภท และตั้งค่าคอนฟิกสภาพแวดล้อมทั้งหมดที่ส่วนกลางเพียงครั้งเดียวเมื่อเปิดเครื่อง พร้อมกลไกการโยนข้อผิดพลาดหยุดแอปพลิเคชันทันทีหากพบค่าที่ไม่เหมาะสม (Fail Fast)

5. **หลีกเลี่ยงผลกระทบข้างเคียงจากการอิมพอร์ตโมดูล (Module Side Effects):**
   ออกแบบโค้ดหลีกเลี่ยงการสั่งรันตัวจับเวลา (Timer) หรือเชื่อมต่อเครือข่ายงานเบื้องหลังทันทีที่เรียกใช้งานโมดูลผ่านคำสั่ง Import เพื่อให้การทดสอบระบบแยกแยะส่วนกันได้ดีขึ้น

6. **การจัดการข้อมูลขนาดใหญ่ด้วย Stream (Streams for Large Payloads):**
   เลือกใช้ Pipeline ในการสตรีมข้อมูลออกทีละน้อยแทนการโหลดเนื้อหาทั้งหมดลงในหน่วยความจำ (RAM Buffer) เพื่อประหยัดทรัพยากรเมื่อต้องดาวน์โหลดหรือประมวลผลข้อมูลปริมาณมาก

7. **วงจรชีวิตและการยกเลิก HTTP Request ตั้งแต่เนิ่นๆ (HTTP Request Lifecycle):**
   ลำดับขั้นตอนตรวจสอบอย่างรอบคอบ เช่น การตรวจเช็ค HTTP Method ก่อนเริ่มอ่านข้อมูลใน Body และกำจัด Request ที่มีขนาดใหญ่เกินพิกัดตั้งแต่ระยะแรก

8. **การปิดระบบอย่างเป็นระเบียบ (Graceful Shutdown):**
   ติดตั้งตัวจัดการสัญญาณระบบ เช่น `SIGTERM` และ `SIGINT` เพื่อระบายคำขอที่ยังประมวลผลค้างอยู่ให้เรียบร้อย และสั่งปิดเชื่อมต่อของฐานข้อมูลอย่างนุ่มนวลก่อนปิดแอปพลิเคชัน

9. **บันทึก Log แบบมีโครงสร้าง (Structured Logging):**
   บันทึกข้อมูลด้วยรูปแบบ JSON ที่มีเสถียรภาพเพื่อให้เครื่องจักรสามารถจัดเก็บและค้นหาสืบค้นง่าย พร้อมระมัดระวังห้ามเก็บบันทึกข้อมูลที่มีความอ่อนไหวสูง เช่น รหัสผ่าน หรือคีย์ส่วนตัว

10. **ความปลอดภัยของตำแหน่งพาธและการตรวจหาข้อมูลนำเข้า (Input Validation & Path Safety):**
    ตรวจสอบตัวแปรชื่อไฟล์ผ่าน RegExp และการตรวจสอบ Absolute Path ด้วยการเทียบส่วนต้นเพื่อป้องกันไม่ให้ผู้ไม่ประสงค์ดีทำการเจาะเข้าถึงไฟล์ภายนอกระบบเป้าหมาย (Directory Traversal)

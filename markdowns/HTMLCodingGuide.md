# สรุปหลักการเขียนโค้ด HTML ที่ดีและแนวทางปฏิบัติ (Good Code Practices)

## 1. การกำหนดข้อมูลเบื้องต้นและภาษาของเอกสาร (Document language and metadata)

**คำอธิบาย:** ควรประกาศข้อมูลพื้นฐานของเอกสารเสมอ เพื่อให้เบราว์เซอร์, ระบบค้นหา (Search engine), และเทคโนโลยีช่วยเหลือ (Assistive technology) เริ่มต้นการทำงานด้วยบริบทที่ถูกต้อง โดยควรระบุภาษาของหน้าเว็บ, การเข้ารหัสตัวอักษร (character encoding), พฤติกรรมของ viewport และกำหนดชื่อเอกสาร (title) ที่เฉพาะเจาะจงและมีประโยชน์ก่อนที่จะเริ่มแสดงผลส่วนเนื้อหา

**ตัวอย่างโค้ดที่ดี:**

```html
<!DOCTYPE html>
<html lang="th">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>หน้าแรก - เว็บไซต์ของฉัน</title>
  </head>
  <body>
    <!-- เนื้อหาเว็บไซต์ -->
  </body>
</html>
```

## 2. โครงสร้างหน้าเว็บเชิงความหมาย (Semantic document structure)

**คำอธิบาย:** ควรใช้แท็ก Landmark และแท็กหัวข้อ (Headings) ที่สื่อความหมาย เพื่อทำให้โครงสร้างของหน้าเว็บเป็นที่เข้าใจได้ง่าย การเปิดเผยโครงสร้างผ่าน Landmark พื้นฐานจะช่วยให้ผู้พัฒนาคนอื่นหรือเทคโนโลยีช่วยเหลือเข้าใจเค้าโครงหน้าเว็บได้โดยไม่ต้องพึ่งพาการอ่าน CSS ดีกว่าการซ่อนความหมายไว้ภายใต้แท็กที่ครอบจักรวาล (Generic containers หรือ Anonymous wrappers)

**ตัวอย่างโค้ดที่ดี:**

```html
<header>
  <h1>โลโก้เว็บไซต์</h1>
</header>
<main>
  <article>
    <h2>หัวข้อบทความ</h2>
    <p>เนื้อหาของบทความ...</p>
  </article>
</main>
<footer>
  <p>สงวนลิขสิทธิ์ 2026</p>
</footer>
```

## 3. การจัดลำดับชั้นของหัวข้อ (Heading hierarchy)

**คำอธิบาย:** ควรใช้หัวข้อ (Headings) เพื่ออธิบายโครงสร้างของเอกสารและสร้างเค้าโครงที่คาดเดาได้ โดยเรียงลำดับจากชื่อหน้าเว็บ ส่วนหลัก และส่วนย่อยตามลำดับ ไม่ควรเลือกใช้ระดับของหัวข้อเพียงเพราะต้องการนำมาเป็นทางลัดในการปรับขนาดตัวอักษร

**ตัวอย่างโค้ดที่ดี:**

```html
<h1>การตั้งค่าระบบ</h1>
<section>
  <h2>บัญชีผู้ใช้งาน</h2>
  <h3>เปลี่ยนรหัสผ่าน</h3>
</section>
```

## 4. ลิงก์และการนำทาง (Links and navigation)

**คำอธิบาย:** หากเป็นการพานักท่องเว็บไปยังจุดอื่น ควรใช้แท็ก Anchor (`<a>`) ที่เป็นลิงก์จริงๆ และมีชื่อระบุปลายทางชัดเจน พร้อมทั้งครอบกลุ่มลิงก์เหล่านั้นด้วย Landmark สำหรับการนำทางที่มีการระบุชื่อ (เช่น `<nav>`) สิ่งนี้ช่วยให้ฟังก์ชันพื้นฐานของเบราว์เซอร์ทำงานได้ปกติ เช่น การเปิดแท็บใหม่ คัดลอกลิงก์ หรือค้นหา

**ตัวอย่างโค้ดที่ดี:**

```html
<nav aria-label="เมนูหลัก">
  <ul>
    <li><a href="/home">หน้าแรก</a></li>
    <li><a href="/about">เกี่ยวกับเรา</a></li>
    <li><a href="/contact">ติดต่อเรา</a></li>
  </ul>
</nav>
```

## 5. รูปภาพและข้อความอธิบาย (Images and alternative text)

**คำอธิบาย:** ควรเขียนข้อความ `alt` (Alternative text) เพื่ออธิบายจุดประสงค์และบริบทของรูปภาพที่มีความหมาย แต่หากรูปภาพนั้นมีไว้เพื่อการตกแต่งเพียงอย่างเดียว ควรซ่อนจากเทคโนโลยีช่วยเหลือโดยการกำหนดค่า `alt` ให้ว่างเปล่าเอาไว้ ทั้งนี้ไม่ควรนำชื่อไฟล์ภาพมาตั้งเป็นข้อความอธิบาย

**ตัวอย่างโค้ดที่ดี:**

```html
<!-- รูปภาพที่สื่อความหมาย -->
<img src="sales-chart.png" alt="กราฟแสดงยอดขายที่เพิ่มขึ้น 20% ในไตรมาสนี้" />

<!-- รูปภาพสำหรับตกแต่ง (ไม่ต้องการให้อ่านออกเสียง) -->
<img src="decorative-divider.png" alt="" />
```

## 6. ป้ายกำกับฟอร์มที่เข้าถึงได้ (Accessible form labels)

**คำอธิบาย:** ควรเชื่อมโยงช่องควบคุมในฟอร์มเข้ากับป้ายกำกับ (`<label>`) ที่มีความทนทานและคงอยู่ถาวร โดยการจับคู่ตัวระบุ (Identifiers) ให้ตรงกัน ไม่ควรพึ่งพาการใช้ข้อความชั่วคราวอย่าง Placeholder เพียงอย่างเดียว เนื่องจากมันจะหายไปเมื่อผู้ใช้เริ่มพิมพ์ และไม่สามารถคงสถานะชื่อกำกับฟอร์มไว้ได้ตลอดการใช้งาน

**ตัวอย่างโค้ดที่ดี:**

```html
<label for="user-email">อีเมลของคุณ:</label>
<input type="email" id="user-email" name="email" />
```

## 7. ข้อความช่วยเหลือและข้อผิดพลาดในฟอร์ม (Form help text and errors)

**คำอธิบาย:** ควรเชื่อมโยงคำแนะนำหรือข้อความแจ้งเตือนข้อผิดพลาดให้เป็นส่วนหนึ่งของช่องกรอกข้อมูลนั้นๆ เพื่อให้เทคโนโลยีช่วยเหลืออ่านสิ่งเหล่านี้ไปพร้อมกับช่องควบคุม การใช้ `aria-describedby` และ `aria-invalid` จะช่วยให้สถานะข้อผิดพลาดผูกติดกับ Input ในแผนผังการเข้าถึง (Accessibility tree) ซึ่งดีกว่าการแค่วางข้อความไว้ใกล้ๆ กันบนหน้าจอ

**ตัวอย่างโค้ดที่ดี:**

```html
<label for="password">รหัสผ่าน:</label>
<input
  type="password"
  id="password"
  aria-describedby="pwd-error"
  aria-invalid="true"
/>
<span id="pwd-error">รหัสผ่านต้องมีอย่างน้อย 8 ตัวอักษร</span>
```

## 8. องค์ประกอบที่โต้ตอบได้ (Interactive elements)

**คำอธิบาย:** เมื่อผู้ใช้สั่งการทำงานใดๆ ควรเลือกใช้คอนโทรลพื้นฐานของ HTML อย่าง `<button>` เป็นหลัก เพราะแท็กปุ่มจะรองรับพฤติกรรมการโต้ตอบผ่านคีย์บอร์ด ลำดับการโฟกัส และ API สำหรับการเข้าถึงมาตั้งแต่ต้น การนำแท็กทั่วไปอย่าง `<div>` มาทำเป็นปุ่มจะผลักภาระให้เราต้องเขียนโค้ดเพื่อจำลองพฤติกรรมพื้นฐานเหล่านี้ด้วยตัวเอง

**ตัวอย่างโค้ดที่ดี:**

```html
<button type="button" onclick="submitData()">บันทึกข้อมูล</button>
```

## 9. ตารางสำหรับข้อมูลรูปแบบตาราง (Tables for tabular data)

**คำอธิบาย:** เมื่อเนื้อหาเป็นข้อมูลที่อยู่ในรูปแบบแถวและคอลัมน์ ควรใช้โครงสร้างมาร์กอัปของตาราง (เช่น `<table>`, `<caption>`, `<th>`, และกำหนด `scope`) เพื่อรักษาสายสัมพันธ์ระหว่างส่วนหัวตารางและเซลล์ข้อมูลเอาไว้ รวมทั้งควรใส่คำบรรยาย (Caption) เพื่ออธิบายภาพรวมของข้อมูลในตารางนั้นด้วย

**ตัวอย่างโค้ดที่ดี:**

```html
<table>
  <caption>
    สรุปยอดขายประจำเดือน
  </caption>
  <tr>
    <th scope="col">เดือน</th>
    <th scope="col">ยอดขาย (บาท)</th>
  </tr>
  <tr>
    <td>มกราคม</td>
    <td>10,000</td>
  </tr>
</table>
```

## 10. ข้อจำกัดในการใช้ ARIA (ARIA restraint)

**คำอธิบาย:** ควรเริ่มต้นด้วยการใช้ความหมายดั้งเดิมที่มีอยู่ใน HTML เสมอ (Native HTML) และเสริมด้วย ARIA เฉพาะในกรณีที่ต้องการอธิบายพฤติกรรมที่ HTML ธรรมดาไม่สามารถแสดงออกได้ หรือใช้เมื่อองค์ประกอบที่มองเห็น (เช่น ไอคอน) ต้องการชื่อหรือคำอธิบายเพิ่มเติมให้ชัดเจนขึ้น การพยายามใส่ roles หรือสถานะที่ไม่ตรงกับความจริงอาจสร้างความสับสนต่อผู้ใช้งานได้

**ตัวอย่างโค้ดที่ดี:**

```html
<!-- ใช้ปุ่มของ HTML และเสริม ARIA เพื่ออธิบายการทำงานของไอคอน -->
<button type="button" aria-label="ปิดหน้าต่าง">
  <svg class="icon-close" aria-hidden="true">...</svg>
</button>
```

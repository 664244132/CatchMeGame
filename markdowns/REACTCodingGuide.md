# React Coding Guide

**ข้อกำหนดและแนวทางปฏิบัติในการเขียนโค้ด React**

1. **Props Component Boundaries (ขอบเขตของ Props ในคอมโพเนนต์):**
   หลีกเลี่ยงการให้คอมโพเนนต์การแสดงผล (Presentational Component) ดึงข้อมูลโดยตรงจาก Application State ที่กว้างเกินไป เพราะจะทำให้คอมโพเนนต์ผูกติดกับระบบภายนอกและทดสอบได้ยาก ควรส่งข้อมูลที่จำเป็นผ่าน Props อย่างเปิดเผยเพื่อให้คอมโพเนนต์มีความเป็นอิสระและยืดหยุ่น

2. **Stable Keys in Lists (การใช้คีย์ที่เสถียรในลิสต์):**
   หลีกเลี่ยงการใช้ Array Index เป็น `key` เนื่องจากบอกเพียงตำแหน่งลำดับในอาเรย์ ไม่ได้ระบุถึงอัตลักษณ์ที่แท้จริงของไอเทมนั้น ซึ่งส่งผลเสียอย่างยิ่งเมื่อลิสต์มีการสลับตำแหน่ง แทรก หรือลบ ควรใช้ไอดีเฉพาะที่ไม่เปลี่ยนแปลง (Stable IDs) เพื่อรักษาตัวตนของไอเทมเสมอ

3. **Derived State (การใช้ค่าสถานะที่คำนวณแทนการซิงก์ซ้ำซ้อน):**
   หลีกเลี่ยงการใช้ `useEffect` เพื่ออัปเดตและเก็บ State ตัวใหม่เพื่อรอรับข้อมูลจาก Props เพราะนอกจากจะซ้ำซ้อนแล้ว ยังเสี่ยงต่อการเกิดปัญหาการซิงโครไนซ์ล่าช้า ควรคำนวณค่านั้นขึ้นมาระหว่างการ Render ได้ทันที

4. **Updating State from Previous State (การอัปเดต State จากค่าก่อนหน้า):**
   เมื่อใดก็ตามที่สถานะถัดไปต้องคำนวณจากสถานะก่อนหน้า ควรใช้รูปแบบ Functional Update (การส่งฟังก์ชันเข้าไปรับค่าล่าสุดจาก React) เพื่อหลีกเลี่ยงการนำ State ที่ถูกบันทึกไว้ใน Render Closure ปัจจุบันไปใช้ ซึ่งอาจส่งผลให้การอัปเดตตกหล่นในกรณีที่มีการเรียกใช้ซ้ำ ๆ อย่างรวดเร็ว

5. **Controlled Form Inputs (การใช้ Controlled Input ควบคุมฟอร์ม):**
   เก็บค่าของแบบฟอร์มไว้ใน React State เสมอ เพื่อให้การตรวจสอบความถูกต้อง (Validation) การอัปเดต และการรีเซ็ตค่าต่าง ๆ มาจากแหล่งข้อมูลเดียว การใช้คำสั่งสืบค้นและแก้ไข DOM โดยตรง (เช่น `document.querySelector`) จะข้ามกลไกข้อมูลของ React และส่งผลให้ทดสอบระบบได้ยาก

6. **Effect Dependencies (ความครบถ้วนของ Dependency ใน Effect):**
   ตรวจสอบและระบุตัวแปรทั้งหมดที่ถูกเรียกอ่านภายใน `useEffect` ลงใน Dependency Array ให้ครบถ้วน เพื่อให้การทำงานของ Effect ตอบสนองต่อการเปลี่ยนแปลงข้อมูลได้อย่างถูกต้อง ไม่นำข้อมูลเก่า (Stale Data) จากการ Render ครั้งแรกมาประมวลผลซ้ำ

7. **Async Effect Cleanup (การล้างการทำงานของ Async Effect):**
   เพื่อป้องกันปัญหาผลลัพธ์ย้อนหลังสลับกัน (Race Conditions) จากการเรียกใช้ API ล่าช้า ควรจัดทำฟังก์ชันล้างผลข้างเคียง (Cleanup Function) เพื่อยกเลิกคำขอเดิม หรือทำเครื่องหมาย cancelled เอาไว้ ป้องกันไม่ให้อินเทอร์เฟซผู้ใช้อัปเดตข้อมูลที่หมดอายุแล้ว

8. **Context Boundaries (ขอบเขตที่เหมาะสมของ React Context):**
   ควรใช้ Context เฉพาะสำหรับส่งข้อมูลแวดล้อมที่จำเป็นในวงกว้าง (Ambient Data) เช่น สิทธิ์การเข้าใช้งาน (Auth) หรือธีมสี อย่าใช้ Context เป็นช่องทางลัดแบบมักง่ายในการผูกคอมโพเนนต์เข้ากับชุดข้อมูลที่กว้างเกินไป (Broad Global Context) เนื่องจากจะทำให้อินเทอร์เฟซเกิดการ Render ใหม่โดยไม่จำเป็นเมื่อข้อมูลส่วนอื่นที่ไม่เกี่ยวข้องเปลี่ยนรูปไป

9. **Memoization When It Helps (เลือกทำ Memoization เมื่อเกิดประโยชน์จริง):**
   ใช้ `useMemo` เพื่อเก็บประจุการคำนวณที่มีต้นทุนการทำงานสูงและจำต้องมีชุดเงื่อนไขที่ถูกต้องเท่านั้น ไม่ควรนำไปใช้กับข้อความธรรมดาหรือฟังก์ชันทั่วไปที่เบามาก เนื่องจากจะได้ไม่คุ้มเสียกับขั้นตอนการตรวจสอบเงื่อนไขของระบบ React

10. **Composition over Prop Flags (ใช้ Composition แทนการสะสม Prop Flags):**
    หลีกเลี่ยงการสร้าง Boolean Props จำนวนมากเพื่อสลับสับเปลี่ยนคุณสมบัติยิบย่อยของคอมโพเนนต์ตัวเดียว เนื่องจากจะเพิ่มความซับซ้อนและเกิดกรณีการส่งค่าที่ขัดแย้งกันเองได้ง่าย แนะนำให้ใช้คุณสมบัติ Named Slots หรือส่งโครงสร้างเป็น `children` เข้าไปแทน เพื่อให้ผู้เรียกใช้งานปรับแต่งหน้าตาคอมโพเนนต์ได้อย่างอิสระ
